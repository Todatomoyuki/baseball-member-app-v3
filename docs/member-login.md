## DBへの適用

新しいコードを公開する前に、`drizzle/0005_lineup_permissions.sql` までの適用が必要です。`0003_normalize_data.sql` が適用済みなら `0004_member_devices.sql`、`0005_lineup_permissions.sql` の順に、`0004` まで適用済みなら `0005` だけを一度適用します。ローカルと本番は別々に適用が必要です。適用済みの移行や、既存データを初期化する `seed.local.sql` は実行しないでください。

ローカルでは、既存の `dist/server/wrangler.json` を使います。

```powershell
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0004_member_devices.sql" --config="./dist/server/wrangler.json"
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0005_lineup_permissions.sql" --config="./dist/server/wrangler.json"
```

本番では対象D1のバックアップを確保し、CloudflareのD1コンソールで **アプリの `DB` バインディングに接続している本番DB** を選んで、未適用の `0004`・`0005` のSQLを順番に実行します。Wranglerを利用する場合も、本番DBのIDを指定した設定を使ってください。`vite.config.ts` のローカル用設定から生成された設定ファイルを、接続先未確認のまま `--remote` で使わないでください。

`0004` は次を追加し、既存の成績・道具・選手・セッション期限を保持します。

- `players.is_admin`：管理者フラグ。
- `member_devices`：端末の識別情報のハッシュと選手IDの対応。
- `sessions.device_hash`：ログインセッションと端末登録の対応。

移行時点の現役選手から、全角・半角スペースを除いた氏名が `安曇幸寛`・`戸田朋幸` と一致する2名を管理者に設定します。本番の表記が異なる場合は、対象の選手IDを確認して `players.is_admin = 1` を設定してください。以後は氏名ではなく選手IDに付随するフラグで判定し、通常の名簿編集では管理者権限を変更できません。

`0005` は `players.can_edit_lineup` を追加します。移行時点で全角・半角スペースを除いた氏名が `安曇幸寛`・`戸田朋幸`・`押野武`・`池原海斗`・`根岸彪雅` と一致する現役選手にだけオーダー編集権限を設定します。既存の管理者フラグ・成績・道具・選手・セッションは変更しません。表記が異なる場合は対象の選手IDを確認して、この5名の `can_edit_lineup = 1` を設定してください。以後の判定は選手IDに付随するフラグを使い、改名しても権限は変わりません。新規登録選手の初期値は0で、一般の名簿保存から権限は変更できません。

WHERE sort_order IS NOT NULL AND is_admin = 1;

## ログインと保存期間

共通パスワードで認証した後、未登録の端末では「あなたの名前を教えてください」と現役の登録選手一覧を表示します。選択するとそのブラウザーを1名に固定します。1人が複数の端末を利用することは可能です。ログアウトや共通パスワード変更後も端末の登録を残し、次回ログイン時に同じ選手を復元します。

端末登録済みのセッションはDB上の `expires = 0` を期限なしとして扱います。Cookieは400日を指定し、認証済みのアクセス時に延長します。延長のためのDB書き込みはしません。ブラウザーの制限・Cookie削除・端末変更によって保存情報が消えることはあり、完全な無期限ではありません。[ChromeのCookie有効期限上限](https://developer.chrome.com/blog/cookie-max-age-expires?hl=ja)

旧セッションは有効期限内なら初回アクセス時に名前選択へ進み、選択完了後に期限なしへ移行します。新規ログイン後、名前を選択するまでの仮セッションは15分です。登録選手から削除されたメンバーのログインは無効になります。

## 成績と管理者権限

成績入力の初期選手はログイン中の自分です。非管理者は選手名を変更できず、自分の成績だけ入力・編集・削除できます。他の選手の成績は閲覧できます。管理者は全選手の成績を編集できます。画面の制限に加え、APIでも変更差分を確認し、他人の成績の削除を含む更新を拒否します。

共通パスワードの変更は管理者だけに表示し、APIも管理者以外を拒否します。変更時は既存のログインセッションを全て無効化し、変更した管理者だけ新しいセッションで継続します。端末とメンバーの対応は維持します。

オーダー編集は安曇・戸田・押野・池原・根岸の5名だけが可能です。対象は打順・守備位置・スタメン・DH投手・ベンチ順・不参加・人数設定・試合情報・大会や相手の候補です。他のメンバーはオーダーを閲覧でき、登録情報では名前・背番号・ふりがなの編集と、選手の末尾への新規登録ができます。新規選手はベンチに入り、既存選手の配置は変わりません。選手削除や参加状態の変更は5名だけが可能です。APIも登録情報の差分を区別して検証し、権限外のオーダー変更は403で拒否します。押野・池原・根岸に管理者権限は付与しません。

**名前の選択は自己申告で、本人確認ではありません。** 共通パスワードを知っている人が未登録のブラウザーで管理者の名前を選ぶと、管理者として登録できます。Cookieを削除した場合も未登録扱いです。他人による管理者名の選択まで防ぐには、個別認証や管理者による承認など別の仕組みが必要です。

通常のチーム・道具・成績の取得は、セッション・端末・管理者・オーダー編集権限を既存のSELECTに結合し、引き続き1 SQLで行います。成績とオーダーの保存権限はその読み取り結果と差分から確認し、追加の認証SELECTは実行しません。保存時のrevision更新でも権限の一致を確認するため、読み取り後に権限が取り消された保存は成立しません。変更なしの定期取得でも現在の権限を返します。ログイン・初回の端末登録・パスワード変更には、登録や無効化のための読み書きがあります。

## 手元での確認項目

- 未登録ブラウザーで共通パスワード入力後に現役選手が表示され、名前を選択するまでアプリデータを取得できない。
- 非管理者で自分が初期選択され、他の選手へ切り替えられず、自分の成績だけ変更できる。
- 管理者で他の選手の成績とパスワードを変更できる。
- ログアウト・再ログイン・ページ再読み込み後も同じメンバーが復元される。
- パスワード変更後、他の端末は新しいパスワードで再ログインでき、名前の登録は引き継がれる。
- 非管理者によるAPI経由の他人成績の変更・試合ごとの削除・パスワード変更が拒否される。
- 安曇・戸田・押野・池原・根岸でオーダーを編集でき、それ以外では編集操作が表示されない。
- オーダー編集権限がないメンバーでも登録情報の名前・背番号・ふりがなの編集と選手追加が保存できる。追加した選手はベンチに入り、削除・参加状態変更は表示されない。
- 権限がないメンバーによるAPI経由の打順・守備位置・試合情報・ベンチ順・不参加・既存選手の削除や並べ替えが403で拒否される。
- 名前を編集してもオーダー編集権限は変わらず、定期取得や再ログイン後にも現在の権限が反映される。
