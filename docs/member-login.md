# メンバーログインと端末の登録

コードと移行SQLを用意した状態です。ビルド・テスト・DB接続・移行の実行はしていません。

## DBへの適用

`0003_normalize_data.sql` が適用済みのDBに、`drizzle/0004_member_devices.sql` を一度だけ適用してから新しいコードを公開します。ローカルと本番は別々に適用が必要です。既存DBに `0000`～`0003` を再適用したり、`seed.local.sql` を実行したりしないでください。

ローカルでは、既存の `dist/server/wrangler.json` を使います。

```powershell
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0004_member_devices.sql" --config="./dist/server/wrangler.json"
```

本番では対象D1のバックアップを確保し、CloudflareのD1コンソールで **アプリの `DB` バインディングに接続している本番DB** を選んで、`0004_member_devices.sql` のSQLを順番に実行します。Wranglerを利用する場合も、本番DBのIDを指定した設定を使ってください。`vite.config.ts` のローカル用設定から生成された設定ファイルを、接続先未確認のまま `--remote` で使わないでください。

`0004` は次を追加し、既存の成績・道具・選手・セッション期限を保持します。

- `players.is_admin`：管理者フラグ。
- `member_devices`：端末の識別情報のハッシュと選手IDの対応。
- `sessions.device_hash`：ログインセッションと端末登録の対応。

移行時点の現役選手から、全角・半角スペースを除いた氏名が `安曇幸寛`・`戸田朋幸` と一致する2名を管理者に設定します。本番の表記が異なる場合は、対象の選手IDを確認して `players.is_admin = 1` を設定してください。以後は氏名ではなく選手IDに付随するフラグで判定し、通常の名簿編集では管理者権限を変更できません。

適用後の確認用SQL:

```sql
SELECT id, name, number, is_admin
FROM players
WHERE sort_order IS NOT NULL AND is_admin = 1;
```

## ログインと保存期間

共通パスワードで認証した後、未登録の端末では「あなたの名前を教えてください」と現役の登録選手一覧を表示します。選択するとそのブラウザーを1名に固定します。1人が複数の端末を利用することは可能です。ログアウトや共通パスワード変更後も端末の登録を残し、次回ログイン時に同じ選手を復元します。

端末登録済みのセッションはDB上の `expires = 0` を期限なしとして扱います。Cookieは400日を指定し、認証済みのアクセス時に延長します。延長のためのDB書き込みはしません。ブラウザーの制限・Cookie削除・端末変更によって保存情報が消えることはあり、完全な無期限ではありません。[ChromeのCookie有効期限上限](https://developer.chrome.com/blog/cookie-max-age-expires?hl=ja)

旧セッションは有効期限内なら初回アクセス時に名前選択へ進み、選択完了後に期限なしへ移行します。新規ログイン後、名前を選択するまでの仮セッションは15分です。登録選手から削除されたメンバーのログインは無効になります。

## 成績と管理者権限

成績入力の初期選手はログイン中の自分です。非管理者は選手名を変更できず、自分の成績だけ入力・編集・削除できます。他の選手の成績は閲覧できます。管理者は全選手の成績を編集できます。画面の制限に加え、APIでも変更差分を確認し、他人の成績の削除を含む更新を拒否します。

共通パスワードの変更は管理者だけに表示し、APIも管理者以外を拒否します。変更時は既存のログインセッションを全て無効化し、変更した管理者だけ新しいセッションで継続します。端末とメンバーの対応は維持します。

**名前の選択は自己申告で、本人確認ではありません。** 共通パスワードを知っている人が未登録のブラウザーで管理者の名前を選ぶと、管理者として登録できます。Cookieを削除した場合も未登録扱いです。他人による管理者名の選択まで防ぐには、個別認証や管理者による承認など別の仕組みが必要です。

通常のチーム・道具・成績の取得は、セッション・端末・管理者情報を既存のSELECTに結合し、引き続き1 SQLで行います。成績の保存権限はその読み取り結果と差分から確認し、追加の認証SELECTは実行しません。ログイン・初回の端末登録・パスワード変更には、登録や無効化のための読み書きがあります。

## 手元での確認項目

- 未登録ブラウザーで共通パスワード入力後に現役選手が表示され、名前を選択するまでアプリデータを取得できない。
- 非管理者で自分が初期選択され、他の選手へ切り替えられず、自分の成績だけ変更できる。
- 管理者で他の選手の成績とパスワードを変更できる。
- ログアウト・再ログイン・ページ再読み込み後も同じメンバーが復元される。
- パスワード変更後、他の端末は新しいパスワードで再ログインでき、名前の登録は引き継がれる。
- 非管理者によるAPI経由の他人成績の変更・試合ごとの削除・パスワード変更が拒否される。
