# 道具のLINE通知設定

道具ごとに「LINEに通知する」「通知しない」を切り替えます。通知しない道具も担当者やメモを保存でき、道具管理画面に表示します。

## 道具管理画面

上部は3列×約3行の道具一覧で、9件を超えた分は一覧内をスクロールします。「LINEに通知する」「通知しない」で表示対象を切り替えられます。

下部の選手カードを長押しして道具へドロップすると担当者が変わり、自動保存されます。選手、道具の順にタップしても担当を変更できます。道具一覧の外にドロップした場合は変更しません。背番号11の選手を指定した場合は、既存の後藤の確認画面を経由します。

選手を選択していない状態で道具をタップすると、担当者・メモ・LINE通知を編集できます。「登録情報」→「道具一覧」からの登録・編集でも同じ設定ができます。担当者の解除は編集画面の「担当者なし」を選びます。

カードには登録氏名の最初の空白まで（苗字）を表示し、読み上げ用の名前にはフルネーム・背番号を使います。空白のない名前は推測で分割せず、そのまま表示します。

## DBへの適用と公開順序

`drizzle/0006_equipment_line_notifications.sql` を、`0005_lineup_permissions.sql` 適用後に一度だけ実行してください。**DBへの適用を済ませてから、アプリと週次LINE Workerの両方を公開します。** `0005` まで適用済みなら今回追加する移行は `0006` だけです。

移行は `equipment_items` に次の1列を追加します。既存の道具はすべて `1`（通知する）となり、担当者・メモ・表示順は保持します。

```sql
notify_line INTEGER NOT NULL DEFAULT 1
  CONSTRAINT equipment_items_notify_line_check CHECK (notify_line IN (0, 1))
```

ローカルでは、既存の `dist/server/wrangler.json` を使用します。

```powershell
npx wrangler d1 execute yg_member_db --local --persist-to="./.wrangler/state" --file="./drizzle/0006_equipment_line_notifications.sql" --config="./dist/server/wrangler.json"
```

本番ではCloudflareのD1コンソールで、アプリと週次Workerの `DB` バインディングが指す同じ本番DBを選び、`0006` のSQLを実行します。Wranglerを使う場合も本番DBのIDを設定したファイルを指定してください。ローカル用に生成した設定ファイルを接続先未確認のまま `--remote` で使わないでください。適用済みの移行や、既存データを初期化する `seed.local.sql` は実行しません。

適用後にアプリを公開し、週次Workerも再デプロイします。旧Workerは通知フラグを参照しないため、アプリだけの更新では送信対象は切り替わりません。

```powershell
npx wrangler deploy --config="./workers/weekly-equipment/wrangler.jsonc"
```

公開後は開いていた画面を再読み込みしてください。APIの道具データでは `notifyLine` に `true` / `false` を必須とし、省略・文字列・数値は保存エラーにします。古い画面からの保存で通知設定を初期値に戻さないためです。

## 取得・保存と週次通知

アプリは通知フラグを既存の道具のSELECTと差分保存に含めます。通常の道具取得は認証・revisionを含めて引き続き1 SQLで、フラグ用の追加問い合わせはありません。

週次Workerは次の条件を既存のSELECTに追加し、「通知する」かつ担当者のある道具だけを取得します。

```sql
WHERE e.notify_line = 1 AND e.holder_id IS NOT NULL
```

対象が0件ならLINEへ送信しません。担当者のない道具は通知対象外です。退団した選手など名簿にない担当者は「不明な選手」として通知します。文面・送信先・毎週金曜の実行時刻は変更しません。

## 手元での確認項目

- 移行後に既存の道具の通知設定がすべて「通知する」で、担当者・メモ・順序が変わらないこと。
- 道具の新規登録・編集で通知設定を保存でき、再読み込み後にも反映されること。
- ドラッグとタップの両方で担当者を変更でき、スクロール領域の外へのドロップでは変更されないこと。
- 担当者変更・メモ編集で通知設定が維持されること。
- Workerの取得結果が「通知する」かつ担当者ありの道具だけとなり、対象0件で送信しないこと。
- 古い画面の `notifyLine` を含まない保存や、真偽値以外を指定した保存が拒否されること。

この変更ではDB接続・移行SQLの実行・LINE実送信・デプロイ・ビルド・ブラウザー操作による確認は実施していません。
